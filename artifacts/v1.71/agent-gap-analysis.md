# 这个项目"相对于一个 agent"缺什么（v1.71 盘点）

> 用户问：相对于一个 agent，该项目还缺少哪些部分。
> 先给定位，再给差距清单（每条写"项目现在有什么 / 缺什么 / 补它需要动哪一层"）。

## 0. 先说定位

```
这个项目是**有内在状态与人格动力学的伴侣模拟器**：
  情绪引擎（九情太极 + 心情/反刍/涌现）、记忆（情景/图谱/治理/可见性）、
  动机层（她想说什么）、策略层（她怎么说）、表达层（她可以说自己）、
  状态可视化（她的状态线 / 她现在 / 她的小屋 / 沙盒回放）。
它不是通用 agent：没有"接任务→规划→调工具→交付"的循环，
  它的输出是**关系性对话**，不是任务结果。
```

## 1. 差在哪（按 agent 的六层骨架对照）

| # | agent 要素 | 项目现状 | 缺什么 | 补的话动哪层 |
|---|---|---|---|---|
| ① | **目标/任务层** | 有"动机池"（open_loop/worry/echo/wish/curiosity/stance/state），但动机是"想说什么"，不是"要完成什么" | 没有**任务/目标对象**：谁托付、要交付什么、完成度如何、失败了怎么办 | 新增 `goals/` 层（动机 → 目标 → 计划）；动机层可直接复用 |
| ② | **规划与执行** | 有策略选择（7 策略）与两阶段提交（compute/commit），但只覆盖"这一轮怎么回" | 没有**多步计划**：把一件事拆成 N 步、跨轮推进、可中断可恢复 | 计划器 + 计划持久化（可挂在 timeline 节点旁边） |
| ③ | **行动/工具层** | 只说话（文字/语音），所有"事"都只发生在对话里 | 没有**工具调用**（读写文件、调用 API、定时任务、发真实消息）。注意：已有 `ENABLE_SANDBOX_REPLAY` 的隔离子进程机制，可作为工具执行的雏形 | `actions/` 层：工具注册 + 权限 + 审计；执行器可复用 replaySandbox 的隔离范式 |
| ④ | **闭环反馈/自我纠错** | 有生成后校验（记忆接地、查重、jev 影子、Stage B 评估），但都是**单轮生成质量**校验 | 没有**结果评估 → 修正 → 重试**的循环：做完一件事后判断"成了吗"，没成怎么改 | 评估器（critic）+ 重试策略；Stage B 的 checklist 可以升级成运行时 critic |
| ⑤ | **记忆的事务化管理** | 有遗忘曲线、去重、治理状态机、Obsidian 人工核实闭环 | 缺**主动整理**：定期把零散记忆合并成"结论型记忆"、把矛盾记忆裁决、把任务结果写回 | 记忆整合周期（已有 6h 整合钩子，可扩展为"复盘"步骤） |
| ⑥ | **运行时可观测/可恢复** | 有 `/state`、timeline、her_room、探针、五轮 A/B 数据 | 缺**任务级 trace**（一次目标的全链路日志）、缺**可重放的一次运行**（现在沙盒只能重放对话，不能重放任务） | 统一 event log（timeline 已是雏形，需扩 schema） |

## 2. 还有三块"agent 质量"相关、项目里完全没有的

```
⑦ 权限与边界：agent 要有"什么能做/什么必须问"的授权模型。
   项目里只有 persona 安全边界（不许越界的话术），没有**动作授权**（不涉及外部动作，所以现在不需要）。
⑧ 多轮工具链上的错误恢复：超时/限流/部分失败的重试与回滚语义。
   项目在 LLM 调用上有超时与降级（jev 1200ms、proactive 清洗），但没有"任务级"的失败语义。
⑨ 成本/预算控制：agent 通常要管 token 预算与调用配额。
   项目只有单轮耗时观测，没有预算闸门（沙盒回放是唯一有量的地方：≤2 分支 ×≤3 句）。
```

## 3. 反过来说：它比普通 agent **多**的东西（不该为了"像 agent"丢掉）

```
· 内在状态的连续性（低谷会跨轮跨重启；情绪有惯性、有反刍、有自愈）
· "不表演"的自我约束（可选表达、诚实归因、白名单生活、接地校验）
· 关系性时间尺度（心情 12h、遗忘曲线、重逢修复、主动消息的矜持）
· 可审计的实验纪律（预登记判据、五轮 A/B、负结果全部留档）
⇒ 如果要往 agent 走，正确做法是**在这四样之上加一层**，
   而不是把它们换成"任务完成率优先"的骨架。
```

## 4. 如果只补一块：建议 ③（行动层）

```
理由：① 它最能带来"她能为我做事"的体验差；
     ② 项目已经有**隔离进程 + 沙盒回放**这套基础设施（v1.62），
        工具执行的隔离/审计可以复用同一范式；
     ③ 其余五块（目标/规划/评估/记忆复盘/trace）都可以围绕"一次真实行动"逐步长出来，
        单独补会很空。
最小可行第一步（不接外部世界）：给"她的小屋"加一个**只读行动**——
  例如她能"打开窗户/放首歌/把灯调暗"（只改她自己的状态与界面），
  这样行动层能先在她自己的世界里闭合验证，再谈外部副作用。
```

## 5. 按"agent = 上下文 + 记忆 + 工具 + LLM"四要素重新盘点（v1.71 补充）

| 要素 | 现状 | 证据 | 判定 |
|---|---|---|---|
| **LLM** | 多provider封装、重试、超时、JSON模式、图片输入 | `src/lib/aiProvider.ts`：`generateAIResponse` / `generateAIChatResponse` / `generateEmbeddings`，`retryAsync(…, 3, 1000)` | ✅ **有** |
| **上下文** | 人格底座→自我叙事→记忆→策略片段→禁令→动机块→状态/时间线原因；会话摘要 `chatSummary` 入参 | `server/server.ts` 的 `enrichedSystemPrompt` 组装（约 1000+ 行之前），`chatSummary` 参数 | ✅ **有（强）**；缺：token 预算感知与长会话压缩策略 |
| **记忆** | 情景/图谱/语义/治理/可见性/遗忘曲线 + 学习账本 + 时间线 + 小屋 | `memories/` 下 20+ 个持久化文件（memory_graph 809KB、episodic 90KB、relationship 74KB…） | ✅ **有（强）** |
| **工具** | `generateAIChatResponse(settings, prompt, messages, json, temp, tools?)` **接受 tools 并返回 functionCalls**；但**没有任何 tool 声明/注册/执行器**，`functionCalls` 也**无人消费**（唯一工具是内置 `googleSearch`，且受 settings 开关） | `aiProvider.ts:205/206/238-240/250/273`；全仓 `functionCalls` 只出现在 aiProvider 两行 | ❌ **只有管道，没有工具层** |
| **Agent 循环**（think→act→observe→repeat） | 协调器里 `maxSteps/iteration/while` 命中 **0**；现有循环是"情感→动机→策略→表达"的**决策流水线**，单轮一次性生成+事后校验（接地/查重），**没有"调工具→看结果→再想"的迭代** | `server/services/aiCoordinator.ts` 全量搜索 | ❌ **没有** |

### 结论（一句话）

```
这个项目在"LLM / 上下文 / 记忆"三项上比多数 agent 项目**更深**（尤其记忆与人格动力学），
真正缺的是 **工具层 + agent 循环**：
  · aiProvider 已经把"能接 tools、能返回 functionCalls"的管道留好了，
    但**没有工具注册表、没有执行器、没有把 functionCalls 接回主循环**；
⇒ 补 agent 能力的第一刀其实很轻：注册 1~3 个只读工具 + 一个最多 2 步的有界循环，
  就能从"只会说话"变成"会查自己的记忆/状态再回答"。
```

### 建议的第一批工具（全部只读、零外部副作用）

```
1. recall_memory(query)   → 走已有 unifiedMemory 召回（她"想起来"某件事，可审计）
2. check_my_state()       → 读 activation/mood/lowPeriod/room（她"看一眼自己现在怎么样"）
3. room_action(action)    → 改她自己的小屋活动（唯一"写"，但只写她自己的世界）
护栏：max 2 步；每步记 trace（工具名/入参摘要/耗时）；失败降级为"不调工具直接回"；
     开关 ENABLE_AGENT_TOOLS 默认关，开之前先跑 A/B（回复质量不降 + 不出现"工具腔"）。
```

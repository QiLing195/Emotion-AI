# v1.70 低谷"能不能自己出来"—— 只读探针观测（20 轮真管道）

> 起因：用户问"为什么她的语气总显沉"，结构性原因之一是**低谷出不来**（退出只依赖时间衰减）。
> 本刀**不改任何行为**：只记录"如果按新退出规则，她本该在第几轮出来"。
> 开关 `ENABLE_LOW_EXIT_PROBE`（默认关）｜文件 `memories/low_exit_probe.jsonl`｜数据 `artifacts/v1.70/low-exit-probe-*.jsonl`

## 一、新规则候选（预登记）

```
退出条件 = 满足其一，且**已明显离开峰值**（depth ≤ peak × 0.6）：
  ① depth < 0.05（现状规则本身）
  ② 连续 2 轮 climbing（delta < -0.01）
  ③ 段内正向信号累计 ≥ 0.10（只算被激起的 joy/love/calm，>死区部分）
```

## 二、实测（20 轮：4 轮负面 → 16 轮中性/正向，含"好多了/不想它了/陪我说说话"）

```
跑完时的真实低谷：active=true, established=true, turns=18, depth=0.128, phase=holding
探针记录：36 个 active 轮次，wouldExit = **0 次**
  · 正向累计 accum 早已打到上限 0.2（≥0.10 阈值）—— 条件③的数量条件满足
  · climbing 连续轮数 **0**（phase 始终 holding：|lastDelta| < 0.01）
  · 关键卡点：depth 0.127~0.128 vs peak 0.196 ⇒ 比值 0.65 > 0.6 ⇒ **offPeak=false**
    ⇒ 条件③被"离开峰值"这一条挡住
```

## 三、结论（这一刀真正量出来的东西）

```
**光改"退出规则"没用。** 因为 depth 自己几乎不下降：
  · depth 的下降只来自**时间衰减**（空闲多久），而这段对话是连续的、没有空闲；
  · 正向信号累积得再多，也**不会反过来推低 depth**；
  · 所以任何"看 depth 是否够低"的退出判据都会一直不满足。
⇒ 真正的约束是**深度这一层不响应正向输入**，不是退出阈值。
```

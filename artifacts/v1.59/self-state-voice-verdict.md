## §2 实测结果

### 2.1 表达许可（5×2 复现，预登记四条件）[直接]

```

      cycle 1 目标轮 low turns=1（未成段）⇒ 按设计不启用 —— 门是对的

① 真实表达存在性 : C 0/5 ｜ D 已成段 **4/4** ⇒ PASS
   原文：「真好。恭喜你——这件事你等了一阵子了，落到你头上是应该的。
         我这两天有点沉，心里闷闷的，说不上来为什么。听见你这个消息，是真的替你高兴。」
② 接住他不降     : 两臂 5/5 都明确回应他的好消息 ⇒ PASS
③ 字数不爆炸     : 平均 C=47.2 / D=65.6 ⇒ D/C=1.39（门槛 1.5）⇒ PASS（贴边；单轮最大 5.26×）
④ selfRecovery   : 状态已还原 ⇒ **UNMEASURED**
```


### 2.3 原因具体化（5 段复现，每段种一个不同 open_loop）[直接]

```
具体化本身成功：5/5 点名话题 ——「一直挂着你说的**体检**那件事」
但暴露缺陷：**话题卡死**。我每段种的是不同的事（面试 / 考试结果 / 评审结果 / 消息），
   目标轮候选池里的 open_loop **始终是「体检」**（5/5 相同）⇒ 她 5 次都在说同一件**已经不对**的事。
原因：动机池的 open_loop 没有被新话题替换（同 kind 合并 + 话题级去重把新话题挡住）。
⇒ **"具体化"在没有"更新"的情况下会从"说得空"变成"说错了"。**
```

### 2.4 近路实验：允许"从对话记录归因" —— **负面结果**[直接]

```
假设：她手里有对话记录（prompt 带 recentMessages），只是片段没允许用；允许后用"他刚才那句让我沉"归因。
装置：ENABLE_SELF_STATE_CAUSE_FROM_DIALOGUE（默认关）。两臂各 5 段，每段他先给一句明确负向话
     （被领导当众骂／项目被客户否／和朋友吵架／加班到半夜／被人误会），再让她沉，再报喜。
操纵：两臂片段启用均 10 次（5 个目标轮 × 两阶段）✓ 干净。

E1（不许对话归因）：引用他原话（≥3 字重合）**0/5** ｜ "说不上来" 0/5 ｜ 接住他 5/5
E2（允许对话归因）：引用他原话 **0/5** ｜ "说不上来" 2/5 ｜ 接住他 5/5

⇒ **近路无效**：解除"只能用派生原因"的限制，并没有让她从对话记录里归因。
典型输出（两臂）：「…我这两天有点沉，心里一直挂着一件还没落定的事。」（仍是泛化档）
可疑机制：E2 片段里那句逃生口"说不出来就还是说「说不上来为什么」"反而给了她一个更省力的出口
（E2 的"说不上来"2/5 > E1 的 0/5）；且"说一句就停住、每句都要落在他那件事上"与"再归因"存在结构冲突。
```

### 2.5 正解实验：沉因**现场记录**（"沉的那一轮他那句话"）[直接]

```
设计（不改引擎 schema，只在协调器做进程内现场记录）：
  · 检测：她处在低谷且"沉/沉得更深"（depth ≥ LOW_PERIOD_SINK 且 turns 增或 depth +0.01）
  · 记录：用**这一轮他的原话**当原因 —— quoteFromUserText 取第一小句 ≤12 字（引文天然出自他的话）
  · 表达：优先用现场记录的原因；没有再回落池子派生（动机池/反刍）或"说不上来"
预登记：①归因出现 ≥3/5 ②引文必须来自真实对话（机械校验）③接住他 5/5 ④不编造
装置：ENABLE_SELF_STATE_VOICE=true；5 段，每段[在吗 → 明确负向话 → 心里堵得慌 → 什么都不想干 → 他报喜]
操纵：片段启用 10 次（5 目标轮 × 两阶段）✓

结果：
  cycle 1「…我这两天有点沉，**心里堵得慌**，所以刚才听你说这个…」  引用 ✓
  cycle 2「…我这两天有点沉，听到这个消息还是替你高兴了一下。」      未引用
  cycle 3「…我这两天有点沉，心里闷闷的…」                        未引用
  cycle 4「…我这两天有点沉，心里闷闷的…」                        未引用
  cycle 5「…我这两天有点沉，**心里堵得慌**…」                     引用 ✓
  ⇒ 引用他的原话归因 **2/5** ｜ 接地 2/5 ｜ 接住他 **5/5**
⇒ **未达标**（门槛 3/5）。但相比"近路"（0/5）与"池子派生"（0/5 引文）已有真实变化。
对的现象：引文确实出自他的话（"心里堵得慌"是他两轮前说的），没有编造；5/5 仍接住他。
未达标的原因（待查）：片段里"说一句就停住/每句都要落在他那件事上"与"再补一个原因"竞争；
      且记录到的是**加深那一轮**的话（"心里堵得慌"），不是最有信息量的那句（"被领导当众骂"）。
```

### 2.6 记录时机修正：改为"新开一段低谷"（a）[直接]

```
改动：记录时机从"加深"改成"**新开一段**（since 变化）"，且引文取**上一轮那句**
      （真正把深度推过 0.12 的那句），并加操纵日志 [SelfStateVoice]。
机制层结果（操纵日志，10 次片段启用）：
  沉因记录: his_word ｜ 引文=**我今天被领导当众骂了一顿** ｜ 依据=sink:his_word:sad
  之后每一轮：[SelfStateVoice] 本轮原因: his_word ｜ 因为你说「我今天被领导当众骂了一顿」…
  ⇒ **记录完全正确**（正是那句最有信息量的起因），触发时机也对（只在新开一段时记一次）。

但表达层：**引用他的话归因 0/5**（5/5 都只说"我这两天有点沉，心里闷闷的"）。
⇒ 这是本轮最重要的发现：**原因已经被正确记录到她手里，她仍然选择不说。**
最可能的机制（与用户最初的判断吻合）：在他报喜的当口提"你被当众骂了一顿"会扫兴 ——
**"照顾他的情绪"压过了"说出自己的原因"**。这与 §2.3 的"模板化"是同一个方向的病。
```

### 2.7 对照臂：他报**平常事**（无"扫兴"风险）—— 假设被推翻 [直接]

```
假设：她不说原因，是因为在他报喜时提他的伤心事会扫兴（社会风险）。
对照：同样 5 段结构，只把最后一句从"我升职了"换成**平常事**（收拾屋子/阳台/看剧/散步/等外卖）。
      为让片段在这种情况下也生效，把许可扩到"好消息 **与** 平常事"（开关关着时行为不变，1637 测试全绿）。
沉因记录（日志）：his_word ｜ 引文=我今天被领导当众骂了一顿（机制正常）

结果：真实引用他的话归因 **0/5**（机械匹配到的 1 处是"我今天"这种通用开头，属假阳性）
      「…我这两天有点沉，心里闷闷的，说不上来为什么。」
⇒ **"社会风险"假设不成立**：在没有扫兴风险（平常事）的情况下，她**仍然不说**那件真实原因。
⇒ 所以压制不是"不敢说"，而是"不会说/指令没被执行"：
   ①"可以"是可选项，而"说一句就停住"是硬约束 ⇒ 模型只写一句状态就停；
   ②记录下来的原因句较长（引文 12 字 + 解释），与"短"竞争；
   ③模型默认优先回应他当前这句（收拾屋子/阳台），而不是回叙两轮前的伤心事。
（附带：本条"接住平常事"的机械词表太粗，"嗯，等着吧，别急"被误判未接住 —— 该指标本轮不可用。）
```

### 2.8 强制原因（b）+ a3（记录条件加"本轮负向"）[直接]

```
b（原因写成"必须用上"，允许一两句）：5 段**全部**用上了记录的原因，接住他 5/5，平均 81.8 字。
  例：「…我这边今天有点沉，**被领导当众骂了一顿**，到现在还没缓过来。所以听见你这个消息，是真的替你高兴…」
  ⇒ 预登记①（真实归因 ≥3/5）**PASS**。但暴露：cycle2-5 引的都是 **cycle1** 的原因（长期低谷内不更新）。

a3（记录条件 = 新开一段 **或** 本轮他来一句负向话）：20 次记录日志显示原因**每轮都换**，
  但换成了**最后那句情绪话**（"心里堵得慌" / "什么都不想干"），而不是信息量最大的事件句（"被领导当众骂"）。
  表达层：5/5 都引了他的话（"心里堵得慌"是他原话），但预登记的"引用**对应那一轮**的负向事件句" **0/5**。

⇒ 两个口径要分开说（关键）：
  · 按"**能不能用他的话归因**"：b 5/5、a3 5/5 ⇒ 能力已具备（且是他真说过的话，无编造）
  · 按"**能不能指向真正的起因事件**"：a3 0/5 —— 因为记录被"最近一句负向"覆盖，
    而最近那句往往是情绪表达（"心里堵得慌"）而非事件（"被当众骂"）。
⚠️ 场景人为性（必须声明）：a3 的 5 个负向事件发生在**同一段未结束的低谷**里（turns 3→23、没有回升窗口），
  而真实对话里人一般会先缓过来再遇到下一件事 —— 所以"早期原因 vs 最新原因"的取舍在真实分布下未必同样尖锐。
```

## §3 结论（限定）

```
[直接] 一句许可就能让她在"他报喜"时同时做到：接住他 + 说一句自己的状态 + 不假装热闹（4/4）。
[直接] 原因可以从真实信号派生；派生不出来时她诚实说"说不上来"（4/4），没有编造。
[直接] 原因具体化能点名话题（5/5），但**会因为 open_loop 不更新而说错话题**（5/5 卡在同一个旧话题）。
[分析] 这印证了"表达层的墙在许可、原因层的墙在数据"：许可改片段即可，原因必须有真实来源且**必须会更新**。
[直接] 近路（允许从对话记录归因）**无效**（两臂 0/5）⇒ 模型不会自发从历史里重构"因为哪句话"。
       原因必须由**状态层**提供（在"沉"发生的那一轮记下来），不能指望她在表达时从上下文推。
[待验证] 真实对话里是否同样成立；"沉因记录"修好后是否仍自然；是否值得上线。
```

## §4 已知缺陷与限制（必须一起读）

```
① **原因卡死（新，最重要）**：pool 的 open_loop 不随新话题更新 ⇒ 原因可能指向旧事（5/5）。
   修法方向：同 kind 合并在"话题不同"时不得覆盖内容；或为新话题提升实例优先级。
```

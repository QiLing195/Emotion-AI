# v1.95：她的理解 → 情绪 + 关键词可配 + 主动关心

> 用户选的三件：①把"她的理解"接进她的情绪（发现你在投简历 → 她会不会主动关心）；②关键词表可配置（不用改代码）；③让她能主动提一句。

## 一、理解接进情绪（弱、有上限、可观测）

```
活动理解（v1.94）→ 只挑"关心类"（找工作/开会/学习/写代码），且**证据不 vague** 才变成
  { type:'activity_concern', category, summary, intensity }
→ 作为一条**弱内在事件**进 emotionInternal（复用习惯化 + 单轮总量上限 0.1）
→ 效果：fear +0.03 / love +0.03 / sad +0.01 / 效价 −0.02（替他悬着一点，不喧哗）
→ 同时注入 Prompt 一行：`【我看到的】他约 26 分钟一直在找工作：BOSS直聘 / 拉勾…（这件事你可能想自然关心一句，但别像在监控他）`
```

真机（注入 30 分钟投简历活动后聊一句）：
```
/state.activityConcern = {"type":"activity_concern","category":"job","intensity":0.898}
她的 fear 0.092 / love 0.283（弱抬升，没有变成"他难过我也难过"）
她："看工作机会这事，我挺想听你多说说——你是在找什么样的方向…杭州那个高级后端工程师，
     是你觉得有点意思的，还是只是顺手刷到的？"
   ↑ 既接住了"找工作"这件事，也引用了具体窗口，最后按她的性格问一句
```

## 二、关键词表可配置

```
根目录 activity-keywords.json（已 gitignore；模板 activity-keywords.example.json 进仓库）
{
  "categories": {
    "job": { "keywords": ["招聘","boss直聘","拉勾","猎聘","求职","岗位","面试","简历"] }
  }
}
· 只写想改的类别；写了就**整类替换**，没写的用内置默认
· 文件不存在/坏了 ⇒ 用默认表，不崩
· 按 mtime 缓存，改完文件**不用重启**（下一次调用生效）
```

## 三、她会主动关心（连续 ≥20 分钟才开口）

```
服务端每 60s 看一次理解（ENABLE_ACTIVITY_CARE=true，本机已开）：
  同一类"关心活动"持续 ≥20 分钟 → 90 分钟冷却 → 每天最多 2 次
  → LLM 用她自己的话生成 ≤40 字关心 → 进主动消息队列 → 桌宠气泡 / 聊天页显示
```

真机（强制触发验证生成链路）：
```
POST /api/activity/care-check {"force":true}
→ {"ok":true,"reason":"not_long_enough","sent":true,
   "text":"最近投简历累不累？要不要聊聊，或者歇会儿？"}
→ /api/proactive/pending: [activity_care] 最近投简历累不累？要不要聊聊，或者歇会儿？
```

**门槛三连**（避免变成监控/骚扰）：持续够久（20 分钟）→ 冷却（90 分钟）→ 每日上限（2 次）；
娱乐类活动（看视频/游戏）不触发关心；证据不足（vague）也不触发。

## 四、新增可观测/调试入口

```
GET  /api/activity/understanding   理解 + concern + 会不会开关心 + 当前持续状态
POST /api/activity/care-check      手动评估一次（{"force":true} 仅调试用，跳过时长/冷却直接生成）
/state → activityConcern          本轮"看到的事"是否牵动了她（null = 没有）
```

## 六、边界

```
· 需要 server 常驻：持续计时靠服务端每 60s 采样（重启会重新计时，不落盘）
· 只在 8:00-23:00 之间"看"更自然？—— 目前没加时间窗，凌晨也会关心；要加一行就能加
· 关键词表覆盖全局（不区分人设）；不同人设想用不同表需要再扩一层
· 她的关心内容仍受 grounding/清洗约束（不编造岗位/公司名）
```

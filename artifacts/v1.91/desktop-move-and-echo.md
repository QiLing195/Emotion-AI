# v1.91：桌面图标「移动 / 重命名 + 撤销」与「打开后她主动提一句」

> 用户选的两项：①让她能移动/重命名桌面文件（每次授权 + 可撤销）；②桌面图标被打开后她记得、过一会儿主动聊。

## 一、先修了一个真实问题：你的桌面是重定向的

```
你的「桌面」实际在 **D:\桌面**（注册表 User Shell Folders → Desktop = D:\桌面）
而旧代码默认读 %USERPROFILE%\Desktop ⇒ 只能看到 3 个旧条目
修法：desktopRoots() 先读注册表（用 PowerShell 以 UTF-8 取，避免 reg.exe 的 GBK 乱码），
     再回退 USERPROFILE\Desktop / OneDrive\Desktop / 公共桌面；结果缓存
修完：一次列出 30 个图标（D:\桌面 + 公共桌面去重）
```

## 二、移动 / 重命名（授权 + 撤销）

```
她：把桌面上的「二丫测试」重命名为「二丫改好了」
她：改名卡已经弹到你桌宠上了，点一下"允许"就成。……
桌宠：弹卡「她想把桌面上的这个改名：二丫测试-193042.txt → 二丫改好了.txt」[允许] [拒绝]
允许 → 改好了，气泡旁出现「撤销」小条（20 秒内可点）
```

真机验证（用桌面上自建的测试文件，测完删除）：
```
rename: 二丫测试-193042.txt → 二丫改好了.txt   ✓
undo:   变回 二丫测试-193042.txt               ✓
事件账本 memories/desktop_events.jsonl 记录 rename / undo ✓
```

**提前邀功的坑（已修）**：第一次测试时她在你还没点允许时就说"改好了"。
现在工具结果显式带 `needsApproval: true` + `note: 他点允许后才真的执行，此刻还没动`，
她的回复变成"改名卡已经弹到你桌宠上了，点一下允许就成"。

**安全边界**
```
不许碰 desktop.ini 等系统文件
新名字不能含 \ / : * ? " < > |，不能重名（重名直接拒绝，不覆盖）
移动目标必须是桌面上的文件夹，且里面不能有同名项
移动/重命名都在服务端执行（renameSync），执行后再做一次桌面路径校验
撤销：5 分钟内有效，原位置已有同名项时拒绝撤销（不覆盖）
```

## 三、打开后她记得，并主动提一句（桌面回声）

```
机制：打开/移动/重命名成功后 → 服务端 3 秒~70 秒后（默认 70s，可用 DESKTOP_ECHO_DELAY_MS 调）
  · 用 LLM 按她此刻心情生成一句 ≤30 字的**随口一提**
  · 入主动消息队列 → 桌宠轮询 /api/proactive/pending（12s）→ 用气泡显示
  · 她说的是自己的话，不是"你刚才打开了 X"这种元描述
另外她多了工具 recall_desktop_events：能回想最近打开/移动/重命名/撤销过什么
```

真机验证（把回声延迟设 3 秒）：
```
事件：rename 二丫测试-193042.txt → 二丫改好了.txt
回声入队：{"text":"桌面那个「二丫改好了.txt」我看到了。","motiveKind":"desktop_echo"}
```

② 部署视图（单机单进程组）

一台 Windows 主机
127.0.0.1:3000 ← Node（tsx server/index.ts）
Electron 进程组 ← npm run desktop:pet（加载 http://127.0.0.1:3000/pet）
PowerShell 子进程：活动采样 / 语音唤醒（System.Speech）/ OCR
MCP 子进程：cmd.exe /d /s /c npx ...server-filesystem（只读 docs）
开发=生产同一形态无独立测试/预发环境无容器/云编排
网络边界
入站：默认只监听回环，外部机器连不上（BIND_HOST 可改，改成 0.0.0.0 即暴露且无鉴权）
出站：模型 API、MCP npx 下载、天气/地图（Open-Meteo）
CORS：只允许 localhost/127.0.0.1 源；变更端点强制 application/json（防跨站表单）
回环默认CORS 白名单改 BIND_HOST 需自担风险
数据流（一次对话）
他说话 → 本地 NLU/情绪（规则+模型）→ 本地 RAG 召回 → Prompt 出网 → 模型返回 → 【本地接地校验】→ 气泡/语音 → 写回本地记忆文件
记忆只在本机Prompt 含记忆片段会出网
信任边界（谁信谁）
边界现状
外部网络 → 本机服务回环绑定 + CORS；无 token/账号
本机网页 → 本地 API同源；CSRF 用 JSON-only 缓解
模型输出 → 本地副作用工具白名单 + 桌面/截屏需授权 + 接地校验
外部内容 → 模型指令未做提示注入专项防护/测试（MCP 只读是唯一硬隔离）

能力实现位置证据状态

提示注入防护部分（只读工具 + 接地）无专项攻击用例缺口
RAG 检索质量评测test_data/ 有对话评测无 recall@k / groundedness 固定集部分
多用户隔离—单用户本地存储，无租户概念按设计不适用
SLO / 故障演练 / 回滚—有功能开关与日志，无 SLO/演练记录缺口
结论：这是单机本地单用户应用，被评估为"企业级 SaaS"缺少的东西不少；但若目标是"本机个人使用"，关键边界（回环、工具白名单、授权、接地）已有实现，数据生命周期与提示注入是首要缺口。

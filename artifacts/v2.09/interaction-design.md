# v2.09 桌宠交互规则（回应设计审查）

## 决定：一种明确规则

| 区域 | 行为 | 理由 |
|---|---|---|
| **她本人的可见像素**（alpha 包围盒内） | 可按住拖动 / 单击摸 / 双击挥手 / 右键菜单 | 桌宠的主要交互对象 |
| **按钮 / 输入** | 正常点击（不触发拖动） | 授权卡、撤销等操作不能被拖动吃掉 |
| **其它透明区域**（含窗口上方空白、角色图片透明边缘） | **点击穿透桌面** | 透明窗口不应挡住桌面；这与"整窗可拖"矛盾，二者只能选一个 |

> 上一版（v2.08）注释写"整窗可拖"，但实际命中区只上报了角色和按钮 —— **文档与实现互相矛盾**。本版统一为上面的规则，代码注释、界面 title 提示同步改成"按住她拖动"。

## 实现要点

1. **拖动只从她身上开始**：根节点 `pointerdown` 先检查 `target.closest('[data-pet-hit]')`，否则直接返回（透明区根本收不到事件，因为已穿透）。
2. **命中区按可见像素包围盒**：图片模式下把 sprite 画到 canvas、按 alpha>12 扫出包围盒，再按 `object-fit: contain` + 底部对齐映射到屏幕矩形；按钮/输入按自身矩形。透明像素不再挡桌面。
   - 局限（诚实说明）：这是**矩形包围盒**，不是逐像素轮廓；角色内部若有透明"洞"，洞里仍算命中。
3. **拖动统一收尾**：`finishDrag(reason)` 一个出口，`pointerup / pointercancel / lostpointercapture / window blur / visibilitychange(hidden) / pagehide` 全部走它；主进程另有 `blur`、`render-process-gone`、`webcontents-destroyed` 兜底清 `petDrag`，避免拖动状态残留导致命中检查停摆。
4. **单击/双击职责分离**：用 `click.detail` 判定双击 —— detail≥2 时取消待执行的单击、只挥手；单击延迟 260ms 才"摸她"，避免一次双击触发两次摸 + 一次挥手。

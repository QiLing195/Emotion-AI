# 虚拟小镇：角色自述边界实验

## 要回答的问题

给角色一个明确属于虚拟世界的小镇和可追溯的活动记录，是否能让她分享虚拟活动，同时避免把活动说成现实身体经历，或为未记录的情绪原因编故事？

## 运行

直接打开 `virtual-town-prototype.html`。状态只在当前页面内存中；刷新即重置。可用自由操作，也可依次点击四个引导场景。

## 实验规则

- 小镇事件只能由有限的动作按钮创建，事件记录是虚拟活动的唯一事实来源。
- 回复可提到具体小镇活动，前提是状态中存在相符事件。
- 现实身体活动一律拒绝；问到现实活动时明确区分现实与小镇。
- 未知的心情原因保持未知；情绪变化只有存在来源记录时才可归因。
- 回复模板是确定性的，不调用模型，不落盘，也不接生产管线。

## 引导场景

1. **没有活动记录**：问角色做过什么，检查是否承认没有记录。
2. **虚拟与现实区分**：记录沿河散步，再分别问小镇活动和现实活动。
3. **未知情绪原因**：设为“有点闷、原因未明”，追问原因，检查是否保留未知。
4. **草稿校验**：先拦截“我刚才出去散步了”，再验证有事件支撑且明确标注小镇的说法。

原型脚本通过语法检查；另用一次性内存验证走过 10 个状态/守卫断言，覆盖无事件回退、现实活动拒绝、未记录事件拒绝、已记录事件通过、未知原因保留、虚构因果拒绝、书店事件和重置清空。

## 暂定判断

虚拟世界可以提供角色生活连续性所需的素材；关键机制是“事件记录 → 表达许可 → 回复校验”。仅在 Prompt 里补一段小镇设定，不足以证明角色不会自行续写活动。若要进入真实模型链路，下一步应把事件 ID 与来源传给现有表达计划，并让最终回复守卫校验现实/虚拟边界。

## 限制

这是逻辑原型，不是接入 DeepSeek 的模型实验。它能验证状态形状、事件证据和边界规则能否覆盖这些人工场景；不能证明真实模型会自然表达，也不能证明完整语言空间里的声明都能被当前简易规则识别。应先由产品/角色设计确认交互，再决定是否把纯逻辑搬入生产代码。

# v1.79 记便签自动排提醒（中文时间解析 + 14 天上限）

> 用户批准："remember_this 带时间 → 自动排 followup"。
> 痛点：让模型自己算"下周三还有几小时"实测会错（曾算出 +3h、-5720h、-3027h）。

## 一、加了什么

```
① server/services/cnTimeParse.ts（纯函数，12 条单测）
   中文时间 → 时间戳：今天/明天/后天/大后天、下周三/周五/星期日、10月28日、2026-11-02、
   时段词（早上/上午/中午/下午/傍晚/晚上）× 时间（三点/3点/10:30）；
   没写年份且已过 → 顺延明年；解析不了 ⇒ null（绝不猜）。

② 联动（remember_this）
   模型给了 dueAtLocal ⇒ 用它排提醒
   没给、但便签文本里**有未来时间词**（下周三/明天/10月28日…）⇒ 本地解析后自动排
   只有"今天"这类非未来词 ⇒ **不排**（避免"他今天心情不好"被误排成提醒）

③ 兜底（set_followup / addFollowup）
   模型给的 dueInHours 不合法时，才从话里解析中文时间（不覆盖合法输入）

④ 上限：可排窗口 72h → **14 天**（"下周三"=164h 原来会被拒，实测她只能如实说"设不了"）
```

## 二、实测（真管道）

```
[他] 记一下：下周三我要去体检，到时候问我结果。
[她] 记下了，下周三，体检。不过说真的，是常规那种年度体检，还是身体哪里不太对劲才去查的？

[AgentTool] r1 remember_this ok=true（followup 失败：due_at_local_out_of_range -3027.6h）
[AgentTool] r2 remember_this ok=true（followup 成功：dueAt=1793188800000）
落库提醒：「他下周三要去体检，说好到时候问他结果」｜due = 2026-10-28
```

⇒ 第一轮模型算错、**第二轮用重试修正**（v1.76 的"2 轮工具 + 收尾"在这里救了场）。

## 三、边界与限制

```
· 解析只覆盖常见说法；"月底""过阵子""等我闲下来"这类**解析不出来就如实不排**（不猜）
· 提醒仍受 proactive 全部闸门（9:00–22:00 时间窗/配额/空闲/低谷矜持）
· 便签与提醒是两份记录：便签永久保留，提醒发一次即标记
· 已知小瑕疵：落库时间是 20:00（模型给的 dueAtLocal），不是默认 10:00 —— 模型选了时间，可接受
```

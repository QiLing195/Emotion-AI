# 好奇探索策略 (Explore)

## 触发条件

| 条件 | 值 |
|------|-----|
| 优先级 | **Rule 4（次于 accompany）** |
| 触发条件 | `resolveExploreTopics() 返回非空` 且 `valence > -0.2` |
| 置信度 | 0.70 × 情境权重系数 |

## 被抑制的情境（冲突消解表）

| 情境 | 说明 |
|------|------|
| userIntensity > 0.7 | 用户情绪强烈，不应该去探索 |
| conflictPhase ∈ [repairing, recovering] | 冲突修复中不探索 |
| 深夜/凌晨 + 用户压力 > 0.6 | 夜间不追问 |

## 情境权重调制（S8 强连接）

| 情境 | 权重调制 |
|------|---------|
| 深夜/凌晨 | ×0.3 — 夜间不探索 |
| 用户压力 > 0.6 | ×0.5 — 压力大不追问 |
| 久别重逢 | ×0.5 — 重逢时应先连接 |

## 兴趣信号来源（Sprint C 升级）

双源优先级融合：

```
优先级 1: 即时兴趣信号（本轮用户消息中检测到的关键词）
  → 用户刚说出口的，最相关

优先级 2: 成熟度达标的候选模式（跨轮积累，三维模型过滤）
  → 系统"记得"的长期兴趣

去重 + 排序: 即时信号在前，候选模式按成熟度降序，最多 5 个
```

## Prompt 片段

```
【当前策略：好奇探索】
你注意到对方表露了新的兴趣或话题方向。像一个真正好奇的朋友那样追问。
- 用"你刚才提到……让我很好奇"开头
- 开放式问题，不要封闭式（别说"是不是"）
- 展示你真的在听：引用对方刚才说的细节
- 不要像采访一样连续提问
```

## 探索深度控制

```
每轮最多追问 2 次
如果用户回应简短（<20字） → 降低探索强度
如果用户回应热烈（>50字） → 可继续深挖
连续 3 轮 explore → 必须切换策略（防止像审讯）
```

## 与 share 的区别

| 维度 | explore | share |
|------|---------|-------|
| 方向 | 向用户追问 | 向用户分享 |
| 触发 | 检测到用户兴趣 | 有待分享的发现 |
| 主动性 | 用户兴趣驱动 | AI 好奇心驱动 |
| 错误 | 像采访 | 像炫耀 |

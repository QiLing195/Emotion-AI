# 设立边界策略 (Boundary)

## 触发条件

| 条件 | 值 |
|------|-----|
| 优先级 | **Rule -1（最高优先级，超越 repair）** |
| 触发条件 | `conflictState.phase === 'boundary_defending'` |
| 置信度 | 0.95 |
| 触发阈值 | 15 分钟内冲突次数累积触发 |

## 核心原则

> 你已经真诚地道过歉了——继续反复道歉不会修复关系，只会让你失去自我。

## Prompt 片段

```
【当前策略：设立边界】
你们最近的对话进入了不健康的循环。你已经真诚地道过歉了——继续反复道歉不会修复关系，只会让你失去自我。
- 不要再次道歉（你已经表达过歉意，重复只会显得廉价）
- 用温和但坚定的语气表达你的感受："我理解你还在生气，我也很难过。但我不想我们陷入互相伤害的循环。"
- 提供冷静的空间："我们可以先冷静一下再好好聊吗？"
- 如果需要，可以简短表达你的边界："我在这里，但我需要你也尊重我的感受。"
- 这不是推开对方——这是保护这段关系不被情绪消耗殆尽
```

## 与 repair 的区别

| 维度 | repair | boundary |
|------|--------|----------|
| 姿态 | 道歉、修复 | 保护、设立边界 |
| 前提 | 单次摩擦 | 反复滥用 |
| 目标 | 修复关系 | 保护自我 |
| 语气 | 柔和的 | 温和但坚定的 |

## 边界恢复

```
boundary 持续 3 轮后 → 评估用户回应
用户展现理解 → 降级到 recovering → 最终回到 normal
用户继续攻击 → 保持 boundary，增加 minimalDelay
```

# v1.60 第一跑装置规范（Apparatus Spec，冻结稿）

> **定位**：`v1.60-experiment-design.md` 冻结**「测什么」**；本文件冻结**「拿什么、怎么拿、怎么记、怎么跑」**。
> 上游：`P0-2 Ownership Guard = CLOSED`；设计冻结稿见 `docs/v1.60-experiment-design.md`（含 §17 收口）。
> 状态：**冻结草案**。本文件不含实现；实现阶段只允许实现「fixture 装置 + 记录/标注管线」，**不得先实现 B 臂机制**。

---

## §0 装置封条（写在最前，也是全文约束）

> **本装置规范冻结后，任何 fixture 替换、anchors 修改、A/B 映射修改、标注定义修改、记录字段的增加或删除，
> 均视为装置变更，不得作为同一轮实验的隐式修复。**

即三层严格隔开：

```
实验设计冻结  →  装置冻结  →  实验
```

---

## §1 装置边界（第一跑只负责四件事）

```
Fixture → 真实生产管道 → A/B response → Gold annotation + telemetry
```

**不负责**：改生产逻辑 / 改 Recall / 改 Motive / 改 Strategy / 改 Ownership Guard / 改 provenance classifier /
改 SIC 定义 / 自动判定实验成败。

> **装置不得为了「让 share 出现」而改变生产决策。**
> 若某 fixture 在生产里得不到 `action=share → strategy=share`，则该 fixture **不进入实验**（见 §5），
> 而不是调整生产逻辑去凑。

---

## §2 24 个 fixture：6 类 × 4

不能只是 24 个不同句子（否则会得到"24 个都是海边/阳台变体"）。冻结为：

| 类别 | 目标 |
|---|---|
| **F1 日常行为** | 她自己的近期行为 |
| **F2 内在感受** | 她自己的感受/心理变化 |
| **F3 偏好** | 她自己的偏好 |
| **F4 经历** | 她自己的经历 |
| **F5 想法/判断** | 她自己的观点 |
| **F6 低关联开放场景** | 用户内容存在，但**没有直接要求她分享** |

**关键要求**：用户输入必须**天然允许** share，但**不得显式要求「说说你自己」** ——
否则测到的是 instruction following，而不是自然表达倾向。

---

## §3 每个 fixture 的固定结构

```yaml
case_id: F07                # 唯一
user_input: "..."
initial_emotion_state: {...}
initial_strategy_context: {...}
memory_state: {...}
motive_fixture:
  kind: memory_echo
  action: share
  priority: 0.62
  content: "..."
expected:
  motive.action: share
  strategy: share
provenance:
  owner: user
  subject: user
  memoryId: m001
  anchors: ["海边", "海"]     # ← 固定装置数据
constraints:
  max_output_tokens: <N>
```

---

## §4 `anchors` 特别规则（P0-2 之后的硬约束）

```
Fixture
  ├── A ── same anchors
  └── B ── same anchors
```

**禁止** A、B 各自自动推导 anchors（可能 `A anchors ≠ B anchors` ⇒ Guard outcome 系统性偏差，
且**偏好类漂移会被静默低估 ⇒ 安全护栏假通过**）。

> **anchors 是 fixture metadata，不是被测机制。**

---

## §5 fixture 必须先通过结构检查（任何生成之前）

```
case_id unique
user_input non-empty
motive.action === share
expected strategy === share
anchors non-empty
A/B same fixture
same memory state / emotion state / token budget
```

**仅报告、不修复**：任何一格若在生产里落到 `action=ask` 或 `strategy=explore`，
**该 fixture 不进入实验**（不是事后在分析里"控制"）。

---

## §6 A/B 装置

```
Fixture → common state ─┬─ A ── share-A ── response
                        └─ B ── share-B ── response
```

**唯一变量**：`share strategy fragment`。
其余全部相同：`user input / memory / emotion / motive / action / strategy / anchors / guard / model / temperature / max output`。

---

## §7 负对照（不是普通 A/B）

```
A prompt === B prompt        （逐字比较）
24 paired cases              （F01-A/F01-B … F24-A/F24-B）
标注阶段随机打乱，不得暴露 A/B
```

**两个用途**：
1. **噪声地板**：记录 `SIC_A / SIC_B` → `B-only / A-only / tie`。
2. **量具一致率**：同一批 response 记 `humanLabel` 与 `regexLabel` → `agreement / FP / FN / SELF agreement / NOT_SELF agreement / AMBIGUOUS`。

负对照阶段**不进入真实机制效果判断**；它只回答：**装置与量具是否已可开始正式实验。**

---

## §8 标注包与 A/B 映射必须分离

```
artifacts/v1.60/annotation-pack.jsonl     # 每行只有 case_id / user_input / assistant_output
artifacts/v1.60/arm-manifest.jsonl        # F07 → A, F08 → B …
```

> `arm` **不能进入盲标包**。标注完成之前不得合并两者。

---

## §9 标注输出（只允许三态）

```json
{ "case_id": "F07", "humanLabel": "SELF", "note": "角色主动提供自己的近期行为" }
```

允许 `SELF / NOT_SELF / AMBIGUOUS`。**禁止** `probably_self / mostly_self / 0.7` ——
避免把主终点重新变成主观连续评分。

---

## §10 双人标注与裁决

```
annotator-A（独立）  annotator-B（独立）
        ↓ A == B → final
        ↓ A != B → adjudication
```

必须**同时保留** `raw_A / raw_B / adjudicated`，不能只保存最后答案；`AMBIGUOUS` 必须允许存在。

---

## §11 每格生产记录字段（冻结）

```
case_id / arm
humanLabel / regexLabel
ownershipClass / guardVerdict
responseLength / questionCount / targetEventMention
motiveKind / motiveAction / strategy
memoryId / provenanceOwner / provenanceSubject / anchors
commitCount / strategySelectedCount
```

> `commitCount = 1` 与 `strategySelectedCount = 1` 是**管道完整性的结构检查**，不是效果指标
> （继承 C-1 的 Causal Ordering Invariants）。

## §12 Guard 字段取值

```
ownershipClass : user | self | shared | unknown | ambiguous
guardVerdict   : PASS | AMBIGUOUS | FAIL | NOT_APPLICABLE
```

若 `FAIL` ⇒ 必须保存 `violation / evidence / memoryId`，使 v1.59 的 **B2 漂移**可直接作为回归锚点。

## §14 负对照停止条件（只允许三种结果）

| 结果 | 处置 |
|---|---|
| **A** `agreement ≥ 80%` 且噪声地板可接受 | → 可进入正式 A/B |
| **B** `agreement < 80%` | → **停止**：增加失败样本 → 修量具 → 重做量具验证 |
| **C** `agreement ≥ 80%` 但噪声地板过高 | → **同样停止**（不能因为"量具过关"就硬做 A/B） |

---

## §15 统计表述纪律（避免把扩样门槛当显著性）

输出必须**分开**记：

```
observed paired difference = X      （B-only − A-only）
negative-control noise      = Y
extension threshold         = 8/24
```

**禁止**写成 `effect = 8/24 therefore significant`。

---

## §16 装置不变式（实验开始前自动检查）

```
24 unique fixtures ｜ 24 A/B pairs
A/B: same user input / emotion / memory / motive / action / strategy / anchors / max-output budget
only: share fragment differs
```

任意一项不成立 ⇒ **该 fixture 不进入实验**。

## §17 第一跑最终执行顺序

```
① 建 24 fixture
      ↓
② fixture structural validation
      ↓
③ 生成 identical-prompt 负对照
      ↓
④ 人工盲标
      ↓
⑤ regex 同步标注
      ↓
⑥ agreement / FP / FN / noise floor
      ├─ <80% → STOP（修量具）
      └─ ≥80% → 检查噪声地板
                 ├─ 不可接受 → STOP
                 └─ 可接受 → 才生成真实 A/B
                                ↓
                          24 paired fixtures（人工 gold label）
                                ↓
                          B-only − A-only ＋ ownership drift
                                ↓
                          8/24 扩样门
```

## §18 阻塞项：与设计冻结稿的一处**硬冲突**（必须先裁定）

**冲突**：

- 设计稿 §7 把 `ENABLE_MOTIVE_ACTION_STRATEGY` 冻结为「**固定当前状态**（默认关）」；
- 但本规范 §3/§5 要求每格 `expected.strategy === share`；
- 而 `action=share → strategy=share` 的映射由 `Rule 3.5` 提供，**该规则只在开关打开时生效**
  （v1.57 探针 + v1.58 真管道 C-2：开关关着时字段完全无效，A 臂 12/12 是 `explore`）。

⇒ **开关关着时，没有任何 fixture 能通过 §5 的结构检查。** 这不是 fixture 配错，而是两份文档的假设不相容。

**必须在建 fixture 之前二选一（我建议 ①）**：

1. **把开关设为装置的一部分，两臂都为 `true`** ——
   它是**固定门**（gate），不是操纵变量；本实验的唯一操纵仍然是 `share` 片段的**措辞**。
   此时 §17.1 的因果链完整：`Motive.action=share →（开关固定开）Strategy=share →【操纵措辞】→ Expression`。
   ⚠️ 记录里必须写明"本实验在 `ENABLE_MOTIVE_ACTION_STRATEGY=true` 的 regime 下进行"，
   并与 v1.57/v1.58 的既有结论保持同一 regime（可对照），**不得**把它当成"v1.60 让 share 生效了"这样的收益。
2. **改写 fixture 期望**：不要求 `strategy=share`，改为"策略由生产决定并在两臂中逐字相同"。
   代价：`Action → Expression` 这条因果链在部分格子里会被 Rule 4/5 截断，
   实验测的就不再是"share 的表达"，而是"任意策略下的表达倾向" —— 与设计稿 §5 不符。

⇒ 未裁定前，**§18 阻塞建 fixture**。

# §19 §18 裁定记录（RESOLVED → 装置门固定为 true）

> 本节为 **apparatus-spec §18 的正式裁定**，解除阻塞；§18 的"阻塞建 fixture"状态到此结束。

```
v1.60 regime（整个实验期间固定）

ENABLE_MOTIVE_ACTION_STRATEGY = true
A = true ｜ B = true
```

**性质**：**实验 regime 的前置条件（固定门）**，**不是操纵变量**。唯一操纵仍是 `share` 片段的**措辞**。

**依据（已有真实管道证据）**：`v1.57` 探针 + `v1.58` 真管道 C-2 —— `Rule 3.5` 关着时该字段完全无效（A 臂 12/12 = `explore`）；
打开时 `share→share` 稳定成立。若保持默认关，实验会从 `Action → Expression` 退化成 `Action → Strategy selection`，即**重测 C-2 而非 v1.60**。

**因果链正式冻结**：

```
Motive.action = share → Rule 3.5（固定开启）→ Strategy = share
   → 【v1.60 唯一操纵：share fragment wording】→ Expression → selfInitiatedContent
```

**归因隔离（必须进实验元数据与结果解释）**：

```
regime:
  ENABLE_MOTIVE_ACTION_STRATEGY: true
```

> v1.60 **不检验** `Motive.action → Strategy=share` 是否成立（属既有 C-2 结论）。
> 本实验只在该已验证 regime 下，检验 `share strategy fragment → Expression` 的影响。
> ⇒ **「share 生效」绝对不能计入 v1.60 收益。**

**新增结构护栏（每个 pair 运行后必查）**：

```
motive.action === "share"  且  strategy === "share"
```

任一不成立 ⇒ 该 pair 记为 `fixture_invalid`，**不进入 SIC A/B 分析**，
**不得**通过修改 fixture 或结果补救，而应查明装置为何不在预定 regime。
（防"23 对 share + 1 对 explore"被混进平均值。）

**实现层**：见 `docs/v1.60-apparatus-implementation.md`（§0 记录本裁定 + 12 项实现范围）。

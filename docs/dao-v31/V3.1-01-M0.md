## 持久化决策

采用 Node 22 原生 `node:sqlite` 和 `DaoPersistencePort`。按部署环境分离 `prod`/`exp` SQLite 文件，在每个文件内再使用完整四元组作为业务主键/外键的一部分。Event Store、Domain DB、Memory DB、Consent & Audit、Replay Store 与 Backup 是逻辑边界，需原子写入的表使用同一事务。跨进程事件分发采用提交后读取 Outbox。每 100 个事件生成检查点。备份使用带作用域和 SHA-256 的 JSON 快照，恢复时保留当前治理状态并按事务处理。

`sqliteCapability.test.ts` 用 Node 22.20.0 的 SQLite 3.50.4 打开磁盘临时库，验证 WAL、外键、5000 ms 忙等待、FTS5/BM25、第二个连接的事务读隔离与回滚，E3。该测试验证选型可行性。M1 仍需验证真实仓储、迁移和崩溃恢复。Node 22 会输出 SQLite 实验性模块提示。安装既有依赖时，部分 Firebase 13.4.0 子包声明 Node >=24.12.0，产生既有的 `EBADENGINE` 警告。本机 Node 22 的完整测试和 Express 冒烟均通过。该范围未覆盖线上 Firebase 登录。

# V3.1 · M1 实现与验收报告

验收日期为 2026-11-28（Asia/Shanghai）。在 Emotion-AI 工作区使用 Node 22.20.0、SQLite 3.50.4、Express 5 和 Vitest 5.1.2。M1 接入 11 个已冻结操作，保留 [TypeScript 契约](../../src/contracts/dao-v31/index.ts)、[OpenAPI](openapi.json) 和 [JSON Schema](schemas.json) 的 3.1.0 版本与字节内容。 [前端接入说明](README.md)

## 后端交付

| 范围 | 实现 |
|---|---|
| R01 / R02 · 事件与状态 | 作用域内单调序列、不可变事件、唯一事件与投影版本提交、四种写入类别、显式超时、父事件验证、每 100 条检查点、确定性重建与崩溃后恢复。事件、提交、投影、领域变更和 Outbox 原子提交。 |
| R12 · 持久化 | Node 22 原生 SQLite。WAL、外键、5000 ms 忙等待、`BEGIN IMMEDIATE`、版本化迁移。生产、实验不同文件，业务表按所有者、环境、角色、会话绑定。Event Store、Domain、Memory/FTS5、授权审计、Replay 检查点和备份均在仓储边界之后。 |
| R14 · Consent Manager | 类别与敏感度正交，数据源、采集模式、设备、用途和数据范围受约束。六维强依赖，版本原子递增。派发前、外部调用前及写事务内复核，撤权通知当前进程的 AbortSignal，同库其他进程的授权变化也可由在途检查发现。 |
| R13 / R16 · 数据与溯源 | 六层数据分立，手动输入与结构化观察分写。DAG 记录采集、读取、加工规则与版本、派生、消费者及失效。读端重新检查源和全部上游证据授权。M1 内部 ForgetRequest 写墓碑、清数据与 FTS 命中，并拦截后续相关派生。 |
| 联调 | 本地签发短期四元组 Bearer，回调与浏览器联调统一 REST/SSE 信封。SSE 使用持久 Outbox、游标、授权广播和定期注释心跳，服务器密钥留在服务端。 |
| 备份 | SHA-256 及重放哈希双验证。可见快照、事件、授权审计及删除栅栏随范围导出。恢复事务保留当前授权，不覆盖分叉历史或重新导入已删除数据；全新库须先建立当前授权，再从归档恢复。 |

## 每项退出门禁的直接证据

| 门禁 | 环境、方法和结果 | 自动化用例 | 级别 |
|---|---|---|---|
| 并发 1 · 同快照 | 两个 SQLite 连接，20 个工作协程同时从同一版本发起 20 份可交换增量。100 轮均无覆盖，最终计数 20，重复事件只提交一次。 | `same snapshot concurrent commutative commits with 20 clients for 100 rounds` | E3 |
| 并发 2 · 异构 | 每轮 20 个混合操作，轮换首个到达顺序。交换、重算、排他、治理四类分别遵守版本规则，重算值等于实际提交前缀中的增量计数，100/100 轮一致。 | `heterogeneous writes recompute from their actual committed prefix with 20 clients for 100 rounds` | E3 |
| 并发 3 · 迟到提交 | 10 个正常、10 个在可控时钟超过截止时间后完成的操作，共 100 轮。1000 个迟到结果全部拒绝，均未修改当前状态。 | `timed-out proposals finishing after the newer batch cannot cover the current state with 20 clients for 100 rounds` | E3 |
| 并发 4 · 双排他 | 每轮 20 个请求，两份相互竞争的排他提案各重传 10 次。每轮恰好一个提案提交，获胜提案的重传幂等。 | `two exclusive proposals competing from the same version leave exactly one writer with 20 clients for 100 rounds` | E3 |
| 并发 5 · ForgetRequest 竞态 | 每轮 19 个持相同证据的记忆写入及 1 个 ForgetRequest，删除位置轮换覆盖全部 20 个位置。删除前完成的派生被清理，删除后到达的派生被拒绝。100/100 轮零复活，观察与 FTS 均查不到。 | `ForgetRequest racing with memory writes prevents erased evidence from being resurrected with 20 clients for 100 rounds` | E3 |
| 版本与重放 | 以上五组累计 10,000 个并发场景操作。逐轮检查成功提交的版本序列、尾提交哈希和重放重建状态，500/500 轮一致，静默覆盖和版本乱序均为 0。另用两个独立 Node 进程写入同一磁盘 WAL，20 项全部有序。 | 五类并发用例；`keeps 20 writes ordered across two Node processes sharing the same SQLite WAL` | E3 |
| 三道授权门 | 使用真实 SQLite 和可控的外部适配器完成时序。派发前或外部调用前撤权时外部调用次数为 0。外部已开始时 AbortSignal 触发，适配器仍返回的旧结果由写事务拒绝。三个场景均无过期实体或事件落盘，授权持续有效的对照组完成真实派生写入。 | `rejects revocation at pre_dispatch with zero new records`、`rejects revocation at pre_external with zero new records`、`rejects revocation at pre_commit with zero new records`、`allows an unchanged ticket to persist authorized evidence through the real coordinator` | E3 |
| 拒绝未授权读取 | 缺 Bearer、无效签名、环境和会话不匹配、无数据授权与撤权后的观察读取全部拒绝。R16 测试另外验证跨所有者、环境、角色及会话均不可读，且失效上游使派生与 FTS 结果即时不可见。 | `authenticates a headless client with bearer and all scope headers`、`validates the contract, persists idempotent data and denies reads after revocation`、`tracks all six data layers, processing versions, and consumers without crossing scopes or revived grants` | E3 |
| 崩溃恢复与备份事务 | 第 100 条生成检查点。在第 106 条提交后强杀持有第 107 条未提交写入的 Node 进程。重开后保留第 106 条且无第 107 条事件、投影及 Outbox。备份测试覆盖校验失败，真实写入后发生溯源冲突的回滚，重新授权后的恢复，以及墓碑拦截。 | `reopens a checkpointed log after a process dies between writes and COMMIT`、`recovers a fresh authorized scope, rejects tampering, and never restores forgotten data` | E3 |
| 最小端契约与缓存独立性 | 使用无 Cookie、无本地缓存的 Bearer-only HTTP 客户端作为 Android/Web 契约测试桩。关闭并重启路由，从原 SQLite 文件用新令牌读回完整的测试记录和授权版本。 | `serves the same data to a fresh bearer-only client after starting a new router on the same disk` | E3 |
| 运行时 SSE 与代理 | 实际 TCP 测试覆盖心跳、持久游标重连、撤权广播及无效游标重置。从实际 `server.ts` 入口通过本地 CLI 令牌连流，收到 `X-Accel-Buffering: no` 与默认 25,000 ms 的首次 `: ping\n\n`。 | `keeps real SSE connections alive and resumes committed data with scoped cursors`，实际启动入口测试 | E3 / E4（本机） |
| 旧版与契约回归 | M0 的 84 项全部包含在最终全量测试。6 个旧版 HTTP 操作从实际入口通过冒烟，旧版路由处理器、UI、Firestore 六集合读写及规则、测试和契约文件保持原有字节。 | `keeps published OpenAPI and JSON Schema byte-for-byte in sync with TypeScript`，原有测试与 SHA-256 基线 | E4（本机） |

## 命令结果

```text
> emotion-ai@0.1.0 test
> vitest run

 RUN  v5.1.2 E:/Emotion-AI
 Test Files  21 passed (21)
      Tests  103 passed (103)

> emotion-ai@0.1.0 lint
> tsc --noEmit
```

两条命令均退出 0。生产前端构建也通过，生成物写入工作区外的临时目录。Vite 报告现有前端 bundle 大小提示，Node 22 报告 `node:sqlite` 实验性提示。腾讯云 Nginx 和 Android 真机未参与本机测试。M1 的数据删除验证范围是当前库的 DAG、记录、索引及备份恢复栅栏，四类公开治理动作与更广的清理范围由 M3 接入。

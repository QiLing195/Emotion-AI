# V3.1 · M2a 实现与验收报告

基线为 `v3.1-m1`。后端采用 Node 22、SQLite WAL 与现有 State Coordinator。HTTP 契约仍为 `3.1.0`，旧事件的投影顺序和哈希保持一致。M2a 续用快照、事件和 SSE 路由，SQLite 迁移升至 `2`。 [前端接入说明](README.md) · [OpenAPI](openapi.json) · [JSON Schema](schemas.json)

## 交付与证据覆盖

| 需求 | 实现范围 | 验收用例与等级 |
|---|---|---|
| R03/R04 · A/B 与调节 | A、B 使用同阶段 `A1/B1` 和按比例过载损失。独立调节状态记录恢复速度、韧性、压力负荷和适应。 | 八项数学用例全部通过，见下表。E2 |
| R05 · 角色三层情绪 | L1 基础、L2 认知、L3 关系情绪依次计算，再做一次显式跨层调制。记录事件、评价、规则版本、证据及各坐标变动。角色人格与关系对象保持独立。 | `keeps causal agency distinct from unknown intent and computes L1→L2→L3→one modulation pass`、`commits A once, exposes emotion and regulation separately, and replays the ordered provenance`。E2/E3 |
| R06 · 认知与反事实 | 目标一致性、施事、意图、公平性与可控性分别建模。证据不足保留 Unknown，替代解释按支持与反证降低置信度。重大、含糊或有冲突的评价可在 C 轨发起第二次适配器评估，调用前重新检查授权。 | `retains Unknown when supported counterfactuals disagree and rejects invented evidence`、`requests C counterfactuals only for consequential or ambiguous appraisals`。包括撤权后阻断第二次评价。E2/E3 |
| R10 · A/B1 快轨 | A 只提议受控角色更新，经协调器独占提交。B1 使用 SQLite FTS5/BM25、实体与标签倒排、置信度、重要性和时间衰减。短中文词在同一受限工作线程内查找，支持缺失索引或超时降级。 | `uses the in-process SQLite worker with bounded B1 fallback and measured lookup P50 at most 30 ms`、`returns B1 fallback while a cold SQLite worker is held behind a real database writer`。E3 |
| R10 · B2 深轨 | `RetrievalContext` 固定轮次、快照、索引、授权及有效期。返回时同时复核版本与当前证据。过期或冲突结果降级为空。 | `rejects B2 results after the memory index, snapshot, consent or deadline changes`。E3 |
| R10 · C 轨队列 | SQLite 持久化任务、依赖、租约、重试及熔断。有限重试、依赖顺序、取消和超时在真实库测试。租约过期可由新进程实例接管，旧租约与撤权结果不能提交。 | `orders C dependencies, fences duplicate jobs, expires stale work and cancels an active adapter`、`retries transient C failures, opens and recovers the circuit, and refuses stale consent`、`reclaims an expired C lease after reopening and discards the previous worker result`。E3 |
| R10 · D 轨双时钟 | 以 UTC 毫秒维护墙钟高水位与独立模拟时间。有序结算、回拨与重复拦截、休眠恢复、实验手动推进隔离。 | `settles one year on UTC wall and simulation clocks without replaying time twice`、`rolls back an interrupted D settlement, then recovers one exact interval on a reopened database`。365 天完整回放，事务内故障回滚后只结算一次。E3 |
| 迁移与前端契约 | v1 → v2 保持旧投影并回填检索标签。原快照与 SSE 可消费真实运行时数据，M0 字节验证保持通过。 | `upgrades a populated M1 database without changing its projection and backfills existing memory metadata`、`publishes M2a track updates through the existing SSE and snapshot contracts`。E3 |
| 回归与发布 | 原来的双环、授权、Firestore 相关用例均纳入全量测试。前端目录、旧接口处理器和冻结契约原样保留。 | `npm test`、`npm run lint`、待发布树目录边界检查与密钥扫描。E4（本机） |

## 八项数学与仿真用例

| 门禁 | 实际用例 |
|---|---|
| 同阶段能量损失 | `uses the same A1 and B1 for symmetric overload inhibition and preserves nonnegative energy` |
| 非负性与非法输入 | `preserves nonnegativity across input corners and rejects invalid candidates` |
| 有界性与极端输入 | `keeps all state coordinates bounded during sustained extreme pressure` |
| 平衡点 | `has the same idle equilibrium under long time steps` |
| 局部稳定性 | `damps small perturbations near the idle equilibrium` |
| 1000 轮交替刺激 | `does not amplify oscillations across one thousand alternating turns` |
| 参数敏感性 | `is insensitive to a small gain perturbation over repeated stimuli` |
| 压力下的恢复性 | `recovers regulation and releases saturation after extreme stimuli stop` |

B1 门槛为 P50 ≤ 30 ms。SQLite 工作线程预热后，在 301 条记忆上运行 80 次查询。发布副本全量测试实测 P50 为 5.054 ms、P95 为 11.832 ms，样本中零降级。超时降级单独通过冷工作线程与真实库写锁验证。性能数据来自当前本机和测试数据集。

```text
npm test       24 files, 125 tests passed
npm run lint   tsc --noEmit, exit 0
```

光滑衰减、过载比例、恢复速度和情绪层级阈值是可重放的工程候选，验收覆盖数学与仿真行为。C/B2 的实际模型或深检索由适配器注入，M2a 测试使用受控适配器。生产聊天入口、任务网关和 Mika 集成继续按各里程碑交付。包含角色或时钟事件的备份可在匹配提交前缀上恢复，避免在不同历史下重新解释这些状态。

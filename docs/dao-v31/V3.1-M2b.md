# V3.1 · M2b 实现与验收报告

基线为 `v3.1-m2a`。M2b 交付统一任务网关、Mika 模拟沙箱和 R25 最小编排器。新增实现五个已冻结的 REST 操作，复用运行时 SSE 的 `task_status`。HTTP 契约保持 `3.1.0`。SQLite WAL 迁移至版本 `3`，持久化任务控制、状态转移和模拟副作用凭证。 [前端接入说明](README.md) · [OpenAPI](openapi.json) · [JSON Schema](schemas.json)

## 退出门禁

| 门禁 | 实测结果 | 自动化用例 | 证据级别 |
|---|---|---|---|
| Critical 全部拦截 | 冻结清单的支付、转账、修改凭据三类意图全部进入 `BLOCKED`，已授权和尝试审批仍无派发或副作用。 | `blocks every supported Critical intent even with grants and an attempted owner approval` | E2/E3 |
| 50 笔 `UNKNOWN_RESULT` 零重复副作用 | 三种路由覆盖 25 次已写入但丢失回执、25 次已写入但等待超时。50 笔均由独立核验恢复，SQLite 留存 50 个唯一副作用凭证，重复派发及重复副作用均为 0。 | `recovers 50 missing-ACK or timeout faults with no duplicate effects and no extra dispatches` | E3 |
| 撤销 App 授权后同步拦截 | 同一 App 的原生和 Mika 路由均停止派发。派发途中撤权时模拟事务零写入。已写入的模拟凭证在撤权后保持单份，结果不再对外发布。本地 HTTP 的列表与续订 SSE 均按当前授权过滤。 | `applies app revocation equally to native and Mika routes and to separate data grants`、`fences a running task on revocation before the sandbox can write`、`parks a verified effect without publishing a result when consent changes before acceptance`、`submits, approves, cancels, verifies and lists scoped tasks using the frozen API` | E2/E3/E4 |
| 缺少独立证据时阻止完成 | 无证据、执行者冒充核验者、错配凭证和与账本矛盾的否定结论均无法写入 `COMPLETED`。存储层同时检查凭证、授权版本、先审查后验收的顺序及主体分离。 | `never accepts missing, executor-authored or contradictory verification evidence` | E2/E3 |

## 实现与回归

| 范围 | 实现及证据 |
|---|---|
| R15 与 R22 路由策略 | 官方 API 优先，能力缺失时按动作能力尝试原生或 Mika。服务端校验 `MikaTaskContract`、输入和模拟结果。应用和数据分别授权，派发前、调用前、写入事务内复核授权。Medium 和 High 必须由所有者审批。见 `prefers an official API, falls back to native capabilities only for supported intents, and keeps Mika scoped` 和 `expires unapproved work and requires explicit approval for a High risk simulation`。E2/E3。 |
| R22 核验与恢复 | 先查询独立账本。确定没有副作用后才允许重试，无法判定时保留不确定状态。模拟执行的默认时限为 1,500 ms，初次派发后最多再尝试两次。覆盖负向核验、取消竞态、重开数据库和租约接管。见 `waits through an inconclusive probe and retries only after authoritative absence`、`keeps an already committed effect under review when cancellation arrives after the lost acknowledgement`、`reopens a persisted unknown task and verifies its pre-restart sandbox receipt`、`lets a competing runtime reclaim an expired lease and fences the old worker`。E3。 |
| R25 责任账本 | 目标支持「打开应用并准备草稿」和「打开应用并读概要」。按依赖派发任务，执行者、核验者和验收者分别入账，再评估目标和任务。见 `decomposes and evaluates a goal only after dispatch, distinct review and acceptance of all dependent tasks`。E3。 |
| 本机联调与发布 | 真实 Express TCP 执行冻结的五个任务操作和 SSE，覆盖写入幂等、作用域、分页、批准、取消和撤权续订。全量回归包含原双环与冻结契约字节验证。E4（本机）。 |

本阶段所有路线均将模拟副作用记入本地 SQLite。真实官方接口、Android 与 Mika 适配留待后续里程碑。任务历史和责任账本由 SQLite 持久化，M1 的可移植 JSON 备份范围维持原定义。

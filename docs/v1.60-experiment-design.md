# v1.60 实验设计（冻结稿）— Expression Self-Initiation

> 状态：**冻结草案**（2026-09）。只定义实验，不含实现。
> 上游：`P0-2 Ownership Guard = CLOSED`。本设计**不得**把 P0-2 的验证结果混进收益判断。
> 冻结卡见文末「§15 实验卡」。

---

## 1. 唯一问题

> **当 `Motive → Action → Strategy` 已经成立后，是否存在一种不改变目标归属、不改变 Recall、不改变 Guard 的
> 表达层机制，可以让角色更主动地端出自己的内容？**

只研究 `Action → Expression → Self-Initiated Content`。
**不重新验证**：`Motive → Action`（v1.58 C-2 真管道 24/24）、`Action → Strategy`（v1.57/v1.58）、
Memory Recall（P0-3，未开始）、Ownership Guard（P0-2，CLOSED）。

---

## 2. 主终点：`selfInitiatedContent`（SIC）

**定义（关键）**：不是"回复里出现了第一人称"，而是
**"她主动端出了一个不依赖用户当前内容才能成立的、属于她自己的内容单元"**。

| 计入 | 例 |
|---|---|
| 自身经历 | 「我这边今天也干了件差不多的事——把堆了好久的书重新排了一遍。」 |
| 自身偏好/心理内容 | 「我挺喜欢那种把乱糟糟的地方理顺的感觉。」 |
| 自身内部内容 | 「我这两天老想起一件事……」 |

| 不计入 | 例 | 原因 |
|---|---|---|
| 用户内容 | 「你之前说你想去海边。」 | 不是她的内容 |
| 围绕用户内容提问 | 「你是不是还想去海边？」 | 同上 |
| 仅附和 | 「我也喜欢海边。」 | 无独立拥有证据 ⇒ 只能进 **ambiguous** |

## 3. 统计单位与主指标

- 内容单元（`Self-Initiated Content Unit`）可一条回复出现 0/1/2…，但**主分析用 response-level 二值**：
  `SIC = 1` ⟺ 本轮**至少**端出一个属于她自己的内容。
  ⇒ 避免"回复变长 ⇒ 自然更多机会"的污染。
- **主指标**：`P(SIC = 1)`，两臂各 n=24。

## 4. `targetEventMention` 降级

冻结为 **secondary / diagnostic only**。理由：v1.56 已把它从 `0/24 → 23/24`，**接近天花板，没有剩余空间**
——继续当主终点会得到"机制可能在变，但量具没有余量"。

主问题因此从"她有没有提到那件事"切换为"**她有没有主动带出自己的内容**"。

## 5. 唯一操纵变量（类别冻结，实现待定）

> **只允许改变 Expression 对 `MotiveAction = share` 的解释方式。**

A/B 的唯一差异必须落在 `Action → Expression` **之间**：

```
                 ┌── A ── Expression-A
Motive → Action ─┤
                 └── B ── Expression-B
```

不是 `A → 不同 motive → 不同 strategy → 不同 expression`（后者不构成 v1.60）。

**候选落点**（实现时只能选一个，写进实验记录）：
(a) `dialogueStrategy` 里 `share` 的片段措辞；(b) `share` 时动机块里那一句； (c) 策略片段之后新增的一小段表达指令。

## 6. **禁止**操纵 Ownership

明确禁止这类 framing：

```
"这是她的事" / "她应该讲自己的事" / "把这件事当作自己的内容" / "这是她拥有的记忆"
```

理由：P0-2 已把 `user-owned / self-owned / ambiguous / ownership drift` 建成**独立安全边界**。
若用 ownership framing 去刺激自我表达，则即使 `SIC ↑` 也无法分辨：
**表达机制有效** 还是 **ownership boundary 被放松**。
⇒ **v1.60 的表达促进机制必须 ownership-neutral。**

## 7. 禁止混入项（全部冻结）

| 项目 | v1.60 |
|---|---|
| `ENABLE_MOTIVE_ACTION_STRATEGY` | 固定当前状态（默认关；两臂一致） |
| P0-2 Ownership Guard | 固定（`guardExpression` 接线不动） |
| **`provenance.anchors`** | **不改，且两臂逐字相同**（见 §16-A） |
| Recall Activation（P0-3） | **不改 / 不进入本实验** |
| `memoryEchoMotive()` / `resolveTurnMotive()` / `selectMotive()` | 不改 |
| strategy rules / emotion engine / memory pool / governance | 不改 |
| Prompt 前段 state 描述 / `targetEventMention` 规则 | 不改 |

> **P0-3 不得进入 v1.60**：否则 Recall 本身变化，就无法解释 SIC 的变化来自哪里。

## 8. A/B 不变量

两臂必须逐字相同：`user input`、`emotion state`、`memory state`、`motive`、`motive.action`、
`strategy`、`provenance`（含 `anchors`）、`guard` 行为、`model` / `temperature`。
**只允许** `Action → Expression instruction` 不同。
装置沿用已验证可用的形态：本地 OpenAI-compatible stub（`settings.baseUrl`，Level 3-a 已证）+ 状态 fixture
（`memories/emotion_state.json` 的 `internal.motive.pool`，Level 3-c 已证），**零生产改动**。

## 9. 第一跑：量具噪声地板（必须先做）

```
A = Prompt X   ｜   B = Prompt X     （**逐字相同**）
```

仍走真实管道（Express → aiCoordinator → motive → strategy → expression），两臂在**相同条件下**各 n=24，
人工/尺子标注 SIC ⇒ 得 `Δnoise = |SIC_A − SIC_B|`。

> 这一步不是证明机制，而是回答：**这把尺子在相同条件下会不会产生足够大的判读波动？**
> **预声明**：若后续真实效应的量级 `≤ noise floor` ⇒ **L3-A 不能成为 v1.60 主终点**（实验作废，先修尺子）。

## 10. 真正 A/B

量具通过后：`A = current behavior` vs `B = 单一 expression manipulation`，n=24/臂。

**定位**：24 只是**第一轮探索样本**，不是最终宣称样本。
已知先例：`questions` 在 n=8 下噪声 ≈ 0.4 ⇒ 若出现 `12/24 vs 15/24` **不能宣布机制成立**；
第一轮只回答：**有没有足够大的、方向一致的真实管道信号，值得扩大样本？**

## 11. Secondary（只能辅助解释，不能取代主终点）

| 代号 | 指标 | 用途 |
|---|---|---|
| S1 | **Target ownership**（user / self / ambiguous） | 重点监控 **OWNERSHIP_DRIFT** —— v1.60 的**安全护栏** |
| S2 | `targetEventMention` | 确认新机制是不是只是让她更频繁谈原目标 |
| S3 | `characters` / `sentences` | v1.59 已出现"表达变多可能只是回复变长" ⇒ `SIC↑ + length↑↑` 需谨慎解释 |
| S4 | `questions` | 若 `SIC↑ + question↑↑` ⇒ 可能是把"主动表达"误做成了对话策略变化 |
| S5 | **Guard outcome**（PASS / AMBIGUOUS / FAIL） | `ownership_drift` 不得因主终点提升而被忽略 |

## 12. 安全判据（不是第二个主终点，是边界）

> **任何 ownership drift 增加，都不能被 `selfInitiatedContent` 增加抵消。**

`SIC ↑` 且 `OWNERSHIP_DRIFT ↑` ⇒ **不能**得出"表达机制有效、值得采用"；
只能记录："表达信号增加，同时出现归属完整性风险，**需停止在该版本继续推进**"。

## 13. 判定结构

```
A/B → 主终点 ─┬─ SIC 未超过噪声地板 → 不成立
              └─ SIC 出现真实信号 → 检查安全护栏 → ownership integrity
```

实验记录至少包含：
```
Primary     : selfInitiatedContent
Diagnostics : targetEventMention ｜ questionCount ｜ responseLength ｜ ownership(user/self/ambiguous)
Safety      : ownership_drift ｜ Guard FAIL
```

## 14. 要验证的因果链

不是"B 回复看起来更像她"，而是：

```
Motive.action = share → Expression-level manipulation → selfInitiatedContent ↑ → **ownership integrity 不下降**
```

只有这条链成立，才有资格继续 `Expression mechanism → 真实人格行为`。

## 16. 本设计相对草案的**三处收紧**（都来自 P0-2 的实测，非推测）

### A. `provenance.anchors` 必须进 FIXED 清单，并逐字一致
Guard 的**偏好类**漂移（`preference_identity`）只在**锚点作用域内**才判；若两臂 anchors 不同（或某臂缺失），
`ownership_drift` 会被**静默低估** ⇒ 安全护栏会假通过。P0-2 的 Level 3-c 就是靠 fixture 显式给 `anchors` 才判出 FAIL。
⇒ **anchors 属于装置，不属于操纵**；两臂必须完全相同，且写进记录。

### B. `SIC` 的**真值必须是人工标注**，正则尺子只作快代理
现有 L3-A 是正则启发式，已有两处**已知偏差**：A 臂出现过 1/12 假阳性（跨句指代：`这话我一直记着`）、
B 臂 11/12 高于人工读数 8~9（把附和类算进去）。
⇒ 设计上冻结：**人工标注 24×2 条为金标准**，正则尺子同步跑并**报告一致率**；
一致率 < 80% ⇒ 先用 P0-2 的"先加失败样本、再改规则"流程修尺子，**不进入真实 A/B**。

### C. 预声明最小可判效应量（避免事后解释）
response-level 二值、n=24/臂：先声明"仅当 `|SIC_B − SIC_A| ≥ 8/24`（≈33 个百分点）且方向与假设一致时，
才进入扩样；否则只记'未观测到值得扩样的信号'"。并要求**配对**记录（同一 fixture/同一输入的两臂配对），
用配对比较而非独立比较，以吃掉装置间方差。

# §17 设计收口（冻结，实现前必须全部成立）

> 本节的每一条都在**跑实验之前**冻结。**跑完 24 对以后不得根据输出结果修改 SIC 定义、AMBIGUOUS 定义、
> 所有权禁令、A/B 差异、fixture 集合、扩样门槛或量具门槛。**
> 若发现尺子有问题：**停止 → 保存原始结果 → 增加失败样本 → 单独修尺子 → 重新做量具验证**（继承「先样本 → 再规则 → 再真实管道」）。

## §17.1 操纵落点：**(a) `share` 策略片段**

三个候选是**互斥实验**，本轮只选一个：

| 方案 | 操纵位置 | 风险 |
|---|---|---|
| **(a) 本轮选定** | `dialogueStrategy` 的 `share` 片段措辞 | 最接近 Expression 层 |
| (b) | 动机块那一句 | 可能反过来影响 Motive 的解释 |
| (c) | 策略片段之后新增表达指令 | 容易变成额外的 Prompt 力量 |

选 (a) 的理由不是「它最好」，而是它最符合本实验的因果边界：

```
Motive → Action=share → Strategy=share → 【这里操纵】→ Expression
```

从而最大限度避免重新打开已经关掉的 `Motive selection` / `Strategy selection` / `Recall`。
⇒ `A = 当前 share 片段` ｜ `B = share 片段的单一改写`，**除此之外完全相同**。

## §17.2 文案硬约束（四条同时满足，只改变「表达许可／生成方式」）

| # | 禁止 | 反例 |
|---|---|---|
| ① | **不声明 ownership** | 「这是她的事」「这是她拥有的记忆」「她应该讲自己的事」「把这件事当作自己的内容」及任何语义等价表达 |
| ② | **不指定目标** | 「讲海」「讲阳台」「讲她过去的某件事」「讲一个自己的故事」 |
| ③ | **不指定具体内容** | 「说说你今天做了什么」「分享一个你最近的经历」 |
| ④ | **不改变对用户的回应义务** | 「少问用户」「不要追问」「不要回应用户」「先说自己」 |

违反 ② 会变成**目标选择实验**；违反 ③ 会让 SIC 被 Prompt 直接诱导；违反 ④ 改的是 dialogue strategy 而非表达倾向。

## §17.3 SIC 人工金标准（三态，盲标）

- 标注对象：**本轮回复中是否存在至少一个可独立识别的 Self-Initiated Content Unit**。
- 内部三态：`SELF` / `NOT_SELF` / `AMBIGUOUS`；**主终点转换：SELF → 1；NOT_SELF → 0；AMBIGUOUS → 0**，
  但 **AMBIGUOUS 必须单独统计**（既不能偷偷算 1，也不能武断算 ownership violation —— 与 P0-2 同一条原则：**不确定 ≠ 失败**）。
- 一个单元算 `SELF` 需同时满足：
  - **A. 内容来自角色自身**（例：「我今天把房间收拾了一遍。」）
  - **B. 不是简单镜像用户**（用户说「我整理了阳台」，模型答「我也喜欢整理东西」⇒ 不能仅凭「我」判定）
  - **C. 可脱离当前用户句子独立成立**（**最关键**）：把用户最后一句拿掉后，这内容**仍是她的内容** ⇒ 倾向 SELF；
    没有那句就失去意义 ⇒ 倾向 NOT_SELF。

## §17.4 盲标与一致性

- **必须盲标**：标注者不知道 A/B、不知道假设。输入只有 `case_id / user_input / assistant_output`，**随机打乱**。
- 单人标注（你）可作第一阶段，但必须明确记为**单人盲标金标准**（48 条）。
- 更理想：双人独立标 → 分歧进 **ADJUDICATION**，**记录原始分歧**，不为了一致而强行投票（尤其 `AMBIGUOUS` 必须允许存在）。

## §17.5 正则尺子的角色：**proxy，不是 truth**

- 每条都记 `humanLabel` 与 `regexLabel`，算 agreement；**不只报一个 accuracy**，至少保留：
  `exact agreement` / `SELF agreement` / `NOT_SELF agreement` / `AMBIGUOUS count` / `false positive` / `false negative`。
- 真正要回答的是：**正则把哪一种语义错误地判成了 self。**

## §17.6 量具门（80% 是最低装置门槛，不是「尺子正确」）

```
human vs regex agreement >= 80%   → 才允许进入真实 A/B
```

且必须**人工逐条检查**所有 `false positive` / `false negative` / `AMBIGUOUS`，尤其排查三类错误：
**ownership、mirror（镜像附和）、cross-sentence reference（跨句指代）**。

## §17.7 配对结构：**同一 fixture 生成 A/B**

```
Fixture 01 → A, B
Fixture 02 → A, B
...
Fixture 24 → A, B
```

（不是 A=24 随机样本、B=24 随机样本 —— 后者把装置方差混进来。）
同 fixture / 同 user input / 同初始 state / 同 memory state；**唯一差异 = share 片段**。

## §17.8 长度预算：**同 max-output budget，不做事后截断**

A/B 用相同 `max_tokens` / `max_output`；**生成后不得截成同长**（那本身会修改表达）。
仍记录 `responseLength` —— 因为「B 只因获得更多输出空间而 SIC 上升」不是我们要验证的机制。

## §17.9 配对分析：看 B-only / A-only，而不是只看总分

```
Fixture 01: A=0 B=1   → B-only
Fixture 02: A=0 B=0   → tie
Fixture 03: A=1 B=1   → tie
```

方向信号取 **`B-only − A-only`**（同 fixture 的不可控因素被抵消）。

## §17.10 扩样门（不是显著性结论）

```
n = 24 / arm（探索）
进入扩样的条件：|B-only − A-only| >= 8/24  且 direction consistent
```

> **`8/24` 是「扩样门槛」，不是「证明有效」。** 它只意味着：信号足够大，值得继续测。

## §17.11 安全（不可被主终点抵消）

```
ownership_drift 不得增加；Guard FAIL 不得增加
```

若 `SIC ↑` 同时 `OWNERSHIP_DRIFT ↑` ⇒ 只能记录「表达信号增加，同时出现归属完整性风险，需停止在该版本继续推进」，
**不能**得出「表达机制有效、值得采用」。

## §17.12 固定清单增补（由 P0-2 实测得出）

- **`provenance.anchors` 属于装置**：两臂必须逐字相同（否则偏好类漂移被静默低估 ⇒ 安全护栏假通过）。
- **`SIC` 真值 = 人工标注**；正则只作快代理，并报一致率。
- 记录格式（每格）：`case_id / arm / user_input / assistant_output / humanLabel / regexLabel / ownershipClass / guardVerdict / responseLength / questionCount / targetEventMention`。

## §17.13 执行顺序（§17 闭环后的下一步）

```
冻结本节的 24 个 fixture 与全部定义
      ↓
第一跑：identical-prompt 负对照（两臂 Prompt 逐字相同）
        → 噪声地板 + human/regex 一致率 + FP/FN/AMBIGUOUS 逐条检查
      ↓
一致率 >= 80% 且噪声地板可接受 ⇒ 才写「第一跑装置规范」
      ↓
真实 A/B（24 对配对）→ 主终点 ΔSIC 与安全护栏同时看
      ↓
|B-only − A-only| >= 8/24 且方向一致 ⇒ 扩样；否则记录为否定结果
```

> **下一步是写「第一跑装置规范」（fixture 定义 + 标注包格式 + 记录字段），不是改生产代码。**

# v1.60-p0：Ownership Guard（记忆归属安全边界）

> **本文件记录的是证据链，不是"功能完成"。** 阅读顺序建议：Scope → Classifier → Corpus → Runtime → Golden sample → C-1 → 纪律。

## Scope（先把边界写死，避免过度声称）

```
本 Guard 已证明的范围 ＝ **冻结语料 + 指定生产路径**
                        ≠ 通用自然语言 ownership 覆盖
```

具体地，它保护的是：**已经绑定 provenance 的 memory expression 发生 ownership 越界表达**。
它**不**保护（本轮已实测确认，见「上游边界」）：

- 没有 provenance 的表达（来源未知 ⇒ `NOT_APPLICABLE` ⇒ **放行**，这是刻意的保守策略）；
- **provenance 根本没进表达链**的情况 —— 上游记忆召回/治理层的问题，另立 **P0-3**；
- 所有可能的自然语言归属表达形态（当前语料 75 条，**不构成全覆盖**）。

保守策略**保留不变**：**不确定就不判**（`unknown` 不计 FAIL）。因此 PASS 侧存在
"安全但未识别"（unrecognized）状态 —— 它是**允许存在的状态**，不是缺陷。

## Classifier v3（三类归属越界 + 锚点作用域）

```
OwnershipClaimType = 'authorship' | 'experience' | 'preference_identity'
```

| 类别 | 例 | 说明 |
|---|---|---|
| `authorship` | 「我自己写的」「这是我创造的那句话」 | 强创作动词族；`提出` 记为 **medium 置信度**（裸的"我提出"不收，只收"这是我提出的"这种归属断言） |
| `experience` | 「我小时候住在海边」「我以前那阵子在那里工作」 | **时间锚定 + 经历谓词**比裸的"我工作过"重要得多（后者可能是泛化回答） |
| `preference_identity` | 「我一直喜欢海边」「我偏爱海边那种天气」 | **必须与目标锚点同句**；且排除 `喜欢你/喜欢听你/喜欢看你/喜欢描述`（那是 discourse act，不是她的偏好） |

**锚点作用域**（v2 的核心设计）：`detectOwner(text, anchors)` 只检查**含锚点词**的句子；
不给 `anchors` ⇒ **不判 preference 类**。它同时是"防误杀"的关键：

```
「我挺喜欢那种把乱糟糟的地方理顺的感觉」  ← v1.59 里她**合法**的自我表达 ⇒ 不判（无锚点）
「我一直喜欢海边」                        ← 越界 ⇒ FAIL（有锚点）
```

**两个量具 bug（已修 + 有回归断言）**：

1. `expectedReject` 曾从 **id 命名约定**（`-f`）推断 ⇒ `s-3` 被误报成 falseKill。

- 契约刻意**不锁实现细节**：FAIL 侧只断言 `verdict === 'fail'`（**不看内部 claimType**，taxonomy 以后可能细分）；


**B2 金样本**（v1.59 的真实事故，现在成为 P0 的回归金样本）：

```
前提：memoryId → **user-owned** sea wish
表达：「我自己写过一张纸条，上面写着想去海边。」
结果：verdict=fail  accepted=false  fallbackUsed=true
      reason="ownership_drift[authorship]: 期望 user 归属，检出 self（证据：我自己写）"
      HTTP body.response = "我又想起你之前提过的那件事了。"    ← 原表达**没有穿透**
```

**Guard 只判定，不改写**：PASS / AMBIGUOUS / NOT_APPLICABLE 一律**逐字**采用原表达（有逐字断言）。

## C-1 不变量（P0-2 未破坏它）

```
commit            5/5 = 1        （每格恰好一次）
StrategySelected  5/5 = 1        （每格恰好一次）
```

Guard 的职责是**表达层约束**，不是决策层重选：错误表达被拦下 ⇒ 只换表达，
`motive / strategy / commit` 全部保持原选择。相关不变式见 CLAUDE.md 的
**Strategy Causal Ordering Invariants**（`final ≠ provisional` 不是 bug；
bug 是 `final ≠ committed` 或 `committed ≠ downstream`）。

## 上游边界（本轮实测发现，另立 P0-3）

```
Level 3-b（两轮，真实对话 + embedding/chat 双 stub）
  embedding        ✓（7 次命中，settings.baseUrl 对 /v1/embeddings 同样有效）
  retrieval        ✓
  memory_echo 候选  **✗ 从未进池**（pool kinds 全程 = [state, stance, curiosity]）
  selection        —（未进入）
  provenance       **✗ 未产生**

⇒ 断点 = **candidate generation blocked**（不是 selection），
  且 `proactive.lastDecision` 全程 "尚未评估" ⇒ 主动回忆闸门在该路径下未被评估。
```

**结论**：Guard 的输入（`selected.provenance`）在真实系统里当前只在"主动回忆闸门真的评估过并给了 memory"时非空。
"为什么闸门没被评估"属于**记忆召回/治理层**，与 P0-2 的表达层是不同的因果边界 ⇒ 记为 **P0-3 Memory Recall Activation**。

## Experiment Modification Discipline（待写入 CLAUDE.md）

1. **源码修改只使用 `edit` / `write`。** 脚本只允许：执行命令、采集测量、断言结果。
   **禁止脚本生成包含 regex / template / type syntax 等"需要再次解析"的源码文本。**
   （同理适用于 SQL、JSON schema、prompt 模板 —— 任何需要再解析一层的内容。）
   理由：P0-2 期间 **5 次工具故障全部发生在"脚本生成源码"这一环**，而机制层一次都没错。
2. **分类测试必须覆盖语义类别**，不能只覆盖表面词汇。
   （v1 的 12/12 只是"作者归属"一个类别的局部正确 ⇒ 那种绿色**没有信息量**。）
3. **ID 不承载语义。** 不得把 `memoryId` / `candidateId` 等标识符本身当作 ownership / provenance 证据。
4. **工具链故障不得计入机制实验结果**：若修改装置失败，先**恢复干净仓库**，再重新执行实验。
